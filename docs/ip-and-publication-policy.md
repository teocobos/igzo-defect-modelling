# IP and Publication Policy

This document provides project-level guidance for handling intellectual
property, unpublished research and public repository content associated
with the IGZO defect-modelling project.

The project forms part of Nanosystems Advisory R&D.

This document is an internal project guideline and is not a substitute
for formal legal advice.

---

## Data Classification

Project information should be considered under four broad categories.

### Public

May include:

- approved source code
- workflow templates
- documentation
- publicly redistributable reference structures
- published methodology
- selected non-sensitive results

### Internal

May include:

- preliminary calculations
- development notes
- convergence studies
- unpublished analysis
- experimental workflow development

### Confidential

May include:

- commercially sensitive research
- proprietary datasets
- collaboration-restricted information
- client-related information

### Restricted

Includes:

- passwords
- SSH private keys
- API tokens
- HPC credentials
- licensed binaries
- redistribution-restricted data

Restricted content must never be committed to GitHub.

---

## Crystallographic Data

Reference structures obtained from public crystallographic repositories
should retain:

- database identifier
- source
- publication reference
- provenance
- relevant redistribution information

The current primary crystallographic reference is:

    COD 1521670

Derived computational models should clearly be identified as derived
structures rather than experimental structures.

---

## VASP

Do not commit:

- VASP executables
- licensed software files
- redistribution-restricted PAW datasets
- licence information

Input templates and scripts that do not contain restricted material may
be included where appropriate.

---

## CP2K, MACE and LAMMPS

Open-source workflow code may generally be committed where compatible
with its licence and project IP policy.

However, unpublished:

- trained models
- proprietary datasets
- optimisation strategies
- commercially valuable workflow details

may require internal review before public release.

---

## Potentially Patentable Results

Before publicly disclosing results that may have commercial value,
consider whether they should undergo an IP review.

Examples could include:

- novel material compositions
- unexpected defect-control strategies
- new predictive models
- commercially useful structure-property relationships
- novel computational workflows with commercial applicability

Public disclosure can affect some forms of intellectual-property
protection.

---

## GitHub Policy

GitHub should primarily contain:

- reproducible research infrastructure
- source code
- documentation
- approved workflows
- small reference structures
- approved figures/results

GitHub should not automatically contain all research data generated by
the project.

---

## HPC and Research Storage

Use controlled storage for:

- raw production calculations
- AIMD trajectories
- large DFT datasets
- MACE datasets
- unpublished models
- commercially sensitive outputs
- intermediate results

---

## Publication Review

Before publication or public data release:

1. confirm authorship/contributor expectations;
2. check collaboration agreements;
3. review potential IP;
4. verify licences and redistribution rights;
5. identify data that can be publicly released;
6. archive reproducible workflows;
7. perform a reproducibility review.

---

## Publication Release

Once approved, consider releasing:

- source code
- input templates
- selected structures
- curated datasets
- trained models where appropriate
- analysis scripts
- figure-generation scripts

Stable public datasets should preferably use an archival research-data
repository rather than GitHub alone.

---

## Repository Principle

The guiding principle is:

> Make the scientific methodology reproducible without unnecessarily
> publishing restricted, proprietary or commercially sensitive data.

---

## Current Repository Release Gate

Before committing newly generated quantitative research results to the
public repository, confirm that the material is appropriate for public
release under the project IP policy.

In particular:

- raw ARCHER2 production directories should not be mirrored wholesale;
- CP2K `*.kp`, wavefunction, restart and other multi-GB runtime files
  should remain on HPC/research storage;
- only selected derived structures, reproducible inputs, analysis
  scripts and approved numerical summaries should be committed;
- commercially sensitive defect trends, trained models or proprietary
  datasets should undergo internal review before public release.

The current crystalline reference structures and numerical summaries
should be treated according to the same release-review principle as
future defect and amorphous results.
